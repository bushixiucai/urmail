## 2. 已确定的实现原则

1. **密码长度分离新写与历史验证。** 新建/重置密码统一按 UTF-8 字节限制最大 256；新密码最低强度与当前面板策略统一。历史验证设置独立的 4096 字节硬上限，与原生 Webmail 既有边界对齐，避免直接把既有 257–4096 字节密码全部锁出。所有超限均拒绝，不能截断。超出历史上限的账号走明确重置路径，不扫描或记录密码明文。
2. **会话以凭据版本为准。** 采用持久 credential version，面板改密、会话撤销及并发登录统一事务协议；不能仅依赖两个顺序 SQL 或时间戳精度。
3. **生产主密钥失效即拒绝启动。** 在 urmaild 业务启动入口校验，避免影响不需要主密钥的只读 CLI/恢复准备命令。测试/开发的显式替身和生产能力分开。
4. **临时内存状态有有效期和总量上限。** 使用现有进程内结构及 PG 有效性复核，无需 Redis。容量满时安全拒绝新增，不能清空全部条目或随机驱逐仍有效用户状态。
5. **未验签请求只留有界元数据。** 合法资金事件的幂等凭据和未决状态继续持久保存；资源清理不破坏到账与退款核对。
6. **退款公平性只改变尚未付款的调度。** 已执行而结果未知的退款仍进入查询/人工核对路径，禁止当作普通失败再次付款。
7. **保留 v80 128 MiB 邮件接收能力。** 归档能力覆盖该 profile 的实际可接受原文及受控的内部新增头开销；通过流式持久化和有界资源预算实现。标准 profile 的大小限制显式化并与既有目标行为核对，不顺手扩大全部入口。
8. **From 保留当前域授权语义。** 严格解析成单一邮箱后核对域；同域 local-part 代发继续按现有策略处理。精确完整地址绑定属于产品策略变更，不作为此次结构解析修复的隐含变化。
9. **生产 HTTP 强制 loopback。** 当前架构由本机 nginx 终止 TLS，不增加尚无需求的远程监听逃生开关。

这些原则消除了常规实现歧义。实施若发现与真实使用合同相冲突的兼容要求，再就具体冲突采访用户，不提前停在风格选择上。

## 4. 逐项实施方案

### SEC-01：密码输入与计算预算

**改动位置：** `internal/domain/mail/password.go`；`internal/api/handlers/auth*.go`、`registration.go`、`platform.go`、`legacy.go`、`mailboxes.go`、`mailbox_password.go`、`mailbox_native.go`；`cmd/urmailctl/setup.go`；相关前端密码表单与 i18n。

- 为新密码策略和历史验证长度定义明确公共规则，覆盖 HTTP JSON、Basic auth、CLI、未知用户 dummy hash 和共享函数。不能只修 `/auth/login`。
- 在任何昂贵计算之前执行字节长度检查；校验 hash 中 rounds 等成本参数的受控边界，历史导入格式需要兼容时列清支持范围。
- 公共认证使用共享有界计算许可，许可申请遵循 context、有界等待和安全拒绝；现有账号/IP 失败预算继续保留。避免 handler 内再开不受控 goroutine 绕过超时。
- 新建/重置最低密码长度统一到面板现有策略，历史较短密码可继续验证，引导正常换密；不静默重置已有密码。
- 接口错误遵循现有 key+params，更新 `api/v1-remediation.openapi.yaml` 和前端提示。

**回归：** 长度上/下边界、Unicode 字节/字符差异、未知用户、Basic/CLI、历史短密码/长密码；hash 调用计数器证明超限从未进入算法；并发许可饱和及取消。测试使用安全小输入和可控替身，禁止用接近 1 MiB 的真实哈希制造负载。

### SEC-02：凭据版本与原子会话撤销

**改动位置：** 新增迁移；`internal/store/queries/auth.sql`、sqlc 输出；`internal/api/handlers/auth.go`、`auth_password.go`、`auth_mfa.go`、`auth_application.go` 及会话中间件。

- 为 panel 用户和 session 增加凭据版本；现有 session 回填与用户一致的版本，既有过期/撤销数据不恢复。
- 改密在平台事务内锁定用户、复验所读密码/版本、更新摘要和版本、删除其他 session、更新保留的当前 session，并写必要审计；失败整体回滚。
- 昂贵密码验证尽量放在锁外；最终发放 session 前在事务内复核验证过的 hash/version，防止旧密码计算完成后迟到发放。MFA challenge 保存初始版本，第二因子成功后同样复核。
- session lookup 校验当前版本；用户停用、租户状态及角色即时复核继续保留。
- MFA 新启用/关闭或种子替换采用明确的认证状态变更事务，撤销其他面板会话和过时 challenge；保留当前已完成安全校验的会话，并更新其版本/验证状态。
- 自动密码摘要格式升级与真实换密区分：单纯 rehash 不应错误撤销其他有效会话。

**回归：** 第二条 SQL 故障整体回滚；取消/并发登录和改密；MFA 中间态跨改密拒绝；当前 session 保留；停用/移除角色立即生效；旧摘要 rehash 竞态不覆盖新密码。

### SEC-03：生产密钥失效与历史明文迁移

**改动位置：** `cmd/urmaild/main.go`、`internal/secrets/box.go`、`internal/api/handlers/auth_mfa.go`、readiness/相关 CLI 和测试。

- 生产启动在启动 listener/worker 前要求有效主密钥；缺失、损坏、不可读均明确失败，日志不包含 key 或种子。
- MFA 写入口独立拒绝 nil Secrets，阻断旁路构造 handler 导致明文写入；其他 secret 写入一起核对。
- 提供受控、幂等的本地 TOTP 明文转 enc:v1 迁移能力，先给只输出数量的 dry-run；显式应用时按批次事务锁行并确认 seed 未变化。有效 enc:v1 不重加密、不误当明文。
- 对历史行采用兼容读取和可见的迁移状态；完成历史数据迁移后再设置拒绝新增明文的 DB 约束，避免新装/历史升级互相阻塞。回退迁移不把密文解密成明文。
- 明确主密钥恢复步骤，禁止自动生成新 key 掩盖旧 key 丢失。

**回归：** 启动失败发生在后台副作用前；所有种子新写均加密；旧明文迁移幂等；损坏密文拒绝；并发 setup 与迁移不覆盖；其他 CLI 只读准备能力正常。

### SEC-04：MFA 与 Webmail 临时状态生命周期

**改动位置：** `auth_mfa.go`、`internal/webmail/session.go`、`mailbox_native*.go`、`middleware/mailbox_auth.go`、`cmd/urmaild/main.go`、必要 sqlc 查询。

- MFA store 注入时钟，记录用户/凭据版本/expiry；issue 前清过期，周期清理无人访问条目；达到失败次数即删除。
- 设置每用户及全局 challenge 上限，首因子成功的 challenge 发放单独限流；容量拒绝具备可观测计数。
- Vault entry 保存 token hash、tenant/mailbox、password version、expiry，接口传递实际 session 生命周期；支持按邮箱统一失效。
- 自助改密/管理员改密后的本进程路径立即失效；外部 agent/CLI 或数据库触发的撤销通过有界批量 PG 复核清理。目标为到期/外部撤销后最多一个清理周期（初始 60 秒）移除凭据；请求发现失效立即清理当前条目。
- 设置全局和每邮箱容量；优先清理已过期记录，仍满时明确拒绝新登录。周期任务随主 context 退出，数据库不可用时停止延长凭据保留期限。
- 一并核对 ScheduleSealer 缓存：只保留可执行任务所需状态，终态/取消/恢复 hold 清理，避免只修 byID 而遗留另一张密码 map。
- 容量值在有界正常负载验证后固定为具名常量或少量配置项，不新增通用缓存框架。

**回归：** 假时钟清理、无人访问过期条目、跨会话改密/管理员重置/CLI 版本变化、容量拒绝不驱逐无关有效用户、race、停止时回收；DB 不可用行为明确。不承诺 Go 内存副本可完全物理清零。

### SEC-05：拒绝回调的存储预算与保留期

**改动位置：** `payment_registry.go`、`platform_payment_registry.sql`、新增迁移、后台维护任务和监控。

- 从业务支付 inbox 分离未验签事件的处理，使用现有 PG 存储有界 metadata：摘要、长度、provider/merchant、错误类别、时间桶和计数；不保存原始正文。
- 按商户/错误/时间桶聚合并限制活跃桶数量；增加全局写入预算，避免“正文变小但仍能无限创建记录”。超预算只增加 bounded metric，不能阻塞合法已验签回调。
- 初始采用 7 天 rejected 元数据保留期，分批清理且索引支持；已验签 completed/processing/uncertain 的业务幂等事实按独立资金留存规则保留。
- 历史 rejected 原文先转换为最小元数据，再由显式维护过程分批清理；不在大迁移事务内全表重写/删除。记录 PG/WAL/备份空间不会因 DELETE 立即归还 OS，提供维护说明。
- invalid 回调的数据库错误与合法资金状态写入失败采用不同响应策略，保证拒绝日志故障不触发业务结算或无界重试。

**回归：** 不同无效正文持久占用仍有界；时间桶/全局预算/TTL；合法验签、去重、payload 冲突及恢复保持；历史清理不触碰未决/合法支付证据。外部 provider 交互仅用本地契约 mock。

### SEC-06：退款退避与公平调度

**改动位置：** `internal/refund/service.go`、`platform_refund_execution.sql`、新增迁移、退款告警/管理读模型。

- 为未执行 approved 退款增加 next_attempt_at、attempt count 等调度事实，已有记录立即可调度。
- 候选按 due time/id 分批选择；provider 构造/凭证读取失败持久化错误和受限退避，再处理其他候选。每轮有批量、时长上限。
- 最终 claim 在事务内 CAS/锁行，多个 worker 不得物理执行同一记录；保留租户 billing 锁与审批前提。
- 若 provider 加载错误无法持久记录，仍采用批次隔离与有界返回，不让同一记录无限占用本轮资源；整体 DB 故障停止派发。
- processing/uncertain 的查询核对和 completed 权益应用也检查逐项错误隔离，避免在相邻循环重复相同队首根因。

**回归：** A 坏商户/B 正常商户跨租户仍公平；退避和恢复；重启/多 worker；错误持久化失败；provider 已接收但响应丢失不重复付款；权益撤销仍精确对应原批准 term。

### SEC-07：归档全链路容量与审计后导出

**改动位置：** `internal/mail/postfix/`、`internal/archive/{spool,read,mime}.go`、`cmd/urmail-archive/main.go`、`archive_content.go`、`middleware/dbtx.go`/受控导出机制、OpenAPI、监控及 golden 文件。

- 定义不同 profile 的显式 SMTP accepted-size 与对应 archive raw-size 上限，覆盖内部新增头的有界开销；保留 v80 128 MiB 合同。通过真实隔离 Postfix 测试确认 SIZE/实际归档字节计数，不能只把两个常量都写 128 MiB。
- Spool 使用受限流式写入、增量 hash、private 临时文件、原子发布、fsync；超限/磁盘满不确认成功，不留下被当作完整副本的 manifest。
- 区分“必须完整保存的 raw”与“可设更低预算的 MIME 索引/预览”。索引提取受限可以降级并明确 extraction_error，但不能把已接受原件截断或静默漏归档。
- 导出在原租户授权、grant、路径归属和完整性校验下准备稳定文件描述符或受控私有快照；同事务写审计并成功提交后才开始响应。
- 使用明确的提交后流式响应能力或独立事务导出路由，普通 JSON 8 MiB buffer 继续有界。校验、审计、读取对象必须绑定同一份内容，避免校验后重新按路径打开的替换窗口。
- 附件采用有界提取/私有临时文件或流式策略，避免完整原文+解码附件+HTTP buffer 多份峰值堆叠；失败/取消后删除临时文件。
- 增加导出并发预算、取消/超时、临时空间和失败告警；传输失败记录已开始/未完成状态，不能声称接收方已收到全部数据。

**回归：** 8 MiB 边界及 16/64/128 MiB 分层样本；profile 上界/超界；独立 BCC 原文头开销；附件哈希；审计失败/提交失败绝不输出内容；双租户、symlink/路径替换拒绝、取消清理、磁盘不足及队列可恢复。大样本重用临时文件和流式生成，限制并发，避免资源消耗测试变成压力攻击。

### SEC-08：From 单一邮箱解析

**改动位置：** `internal/mail/frombind/{map,decision,authorizer}.go`、milter 集成及测试。

- 生产授权基于 `net/mail` 解析结果，明确一个 From 字段且只有一个 mailbox；结构错误/列表拒绝。
- 从解析后的规范 address 提取域并匹配授权集合；域大小写、末尾点、IDNA 等处理与现有 canonical domain 规则保持一致。
- 保留 envelope 精确身份限制、域授权合同及 submission fail-closed；普通入站 25 不引入本地用户授权条件。
- 对 SMTPUTF8/不支持语法给出明确拒绝规则，不做不可靠的字符串修补。

**回归：** 展示名、注释、折行、引用、列表、多字段、无效结构、规范化；同域与跨域结果符合现有策略；真实隔离 Postfix 的 EOH/milter 结果和 DKIM 链在全部 profile 保持一致。

### SEC-09：生产 loopback 校验

**改动位置：** `internal/config/config.go`、配置测试、安装配置说明。

- 所有模式要求 net.SplitHostPort 可解析，host 为明确的 IPv4/IPv6 loopback literal，port 合法；拒绝空 host、0.0.0.0、:: 和公网地址。
- 保留默认 `127.0.0.1:8080`；nginx trusted proxy、TLS 及 metrics 的内部边界一致。

**回归：** 生产和开发两模式的 IPv4/IPv6、端口边界、无效/通配/公网拒绝；默认安装配置正常。

| MFA 变更后旧状态 | 随 SEC-02 撤销其他 session/challenge，明确当前会话保留条件 | 角色撤销和 MFA 变更集成测试 |
| CI/发布约束 | 固定通用 CI action SHA、显式最小 permissions；发布要求目标 SHA 必要 CI 成功，明确 workflow_dispatch 行为；依赖扫描/报告绑定源码与锁文件 | 未通过/未知/错 SHA 的 CI 不发布；构建打包签名的隔离验收 |
| 全量依赖与系统补丁 | 对精确版本进行 Go reachable SCA、npm 生产/开发拆分审计，逐条复核命中；生成系统包清单与补丁检查步骤 | 已确认命中有修复或不适用证据；无数据/工具不可用时明确保留门禁，不填“零漏洞” |
| 进程资源预算 | 为 HTTP hash、导出、archive pipe/worker、维护批次设置局部并发/容量；基于真实邮件并发测量制定 systemd MemoryHigh/MemoryMax 等预算 | 有界正常负载与故障测试；OOM 不导致邮件虚假确认；不随意固定过低配额造成丢信 |
| 密钥轮换与备份 | 形成旧/新 key 共存、重加密、回退/恢复的具体流程；明确签名 key 轮换信任链；补离机加密、保留期及隔离恢复步骤 | 隔离恢复可读历史 secret、hold 保留；实际 key 管理状态由授权运维核实 |

| 生产公网与运维 | loopback/防火墙/IPv6、DB ACL、文件权限、timer、告警送达、DDoS、RPO/RTO 等逐项检查 | 运维只读核对及授权演练记录；未确认项保持未完成 |

Argon2id 的迁移需要发布兼容处理：旧应用不识别新 hash 时不能直接回退二进制。先具备双格式读能力，再开启新写；回退必须使用同样支持双格式的兼容版本。不能“降级”已有密码摘要，不能为了回退保存明文。

## 6. 数据库迁移、接口和兼容交付

- 当前 schema 为 0079；新增迁移按实施时最新编号顺延，不预先占用或改写已有迁移。
- 预计迁移域：panel 凭据版本、历史 TOTP 写入约束、拒绝回调元数据/索引、退款调度。按根因拆分，均提供 up/down 与 sqlc 输出。
- 大表历史清理使用可重入维护批次，不塞进 DDL 迁移；dry-run 只输出数量/状态，不能输出 secrets/payload。
- 新增 schema 默认值使历史数据安全兼容；升级前/后分别检验已有 session、退款、合法 webhook 状态；down 不让 uncertain/held 变回可自动执行状态。
- schema 回滚和应用回滚分别设计。新安全版本启用后，不允许旧应用忽略 credential version 等机制而继续提供服务；交付最小兼容版本和停写/恢复步骤。
- API 契约记录密码规则、容量拒绝、流式下载错误、会话失效及兼容范围；引用现有 OpenAPI，不新增第二套重复接口真相。
- 前端文案同时维护 zh-CN/en，复用现有错误 key 模式，不返回本地化后端字符串或暴露系统错误详情。

## 7. 验证与关闭标准

### 7.1 单项验证

每项采用能在原实现上失败的针对性回归，覆盖正常、拒绝、故障和必要并发路径。测试必须经过真正决定行为的边界：SEC-02 使用真实 PG 事务，SEC-07 经过真实路由/审计/事务层，SEC-08 使用真实隔离协议链。mock 测试不能替代这些层。

外部支付/DNS/AI 交互使用本地契约 mock，禁止意外访问真实服务；按 Postman API 工程流程复用既有契约。实例、数据库及文件均独占且可丢弃，不迁移 URL 指向的既有数据库。

### 7.2 最终统一门禁

1. `make build`、`make lint`、`make i18n-check`、sqlc 漂移检查通过。
2. Go 全量 race 测试及真实本地 PG 集成通过；沿用 `-p 1` 避免测试夹具共享 cluster role 的已知冲突，不能隐藏实际失败。
3. 前端类型、lint、测试及相关浏览器回归通过。
4. 隔离 Linux Postfix/Dovecot/HTTP 的认证、From、归档、下载、账号撤销及定时不重放验证通过。
5. 新装/升级与迁移 up/down 在一次性环境验证；deb 内容、签名、root/非 root 服务权限检查通过。
6. 所有变更二次审查，复查 RLS、platform pool、root agent、审计、secret、取消/重试边界，确认没有为了修可用性而削弱授权。
7. 依赖/镜像/二进制版本和证据绑定最终 Git SHA、diff/锁文件/包摘要。历史 PASS 不计作当前结果。

### 7.3 状态与证据

使用逐项状态：`PLANNED → IMPLEMENTED → VERIFIED → CLOSED`。只有代码、回归、交叉边界审查均通过才 CLOSED；部署未知项另外跟踪，不能被代码 CLOSED 自动勾选。

保留原审查报告作为历史基线，新增 `docs/security/SECURITY_REMEDIATION_RESULT.md`，列出每项修复文件、迁移、测试命令/结果、源码 SHA、限制和剩余环境门禁；证据按批次放入 `docs/reviews/evidence/security-remediation/` 或既有适用目录，脱敏后保存。不写入完整 key、密码、真实邮件或未验签原文。

## 8. 发布结论如何更新

仅修 SEC-01 不代表全部修完。本轮目标是 **9 项全部 CLOSED**，补充加固有对应实现/验收证据，部署缺口逐项有状态。

存在已确认阻断问题时保持 BLOCKED；代码问题全部关闭但关键生产条件未核实时为 CONDITIONAL；完成本轮范围且没有已确认阻断后，才能按证据决定是否达到 READY FOR FURTHER VALIDATION。任何结论都不能表述为已完成全面安全验证。

实施顺序固定从 A 开始，完成每批就记录证据并推进下一批；不以关闭 P1、通过 healthz 或只跑单元测试作为整个任务完成标准。
